# Skill: hypothesis-driven problem solving

1. **Scope before solving.** Restate the question as one decision the client must make,
   with the success metric, the horizon and the constraints. Ask clarifying questions
   up front; confirm the restated question with the client.
2. **Build a MECE issue tree.** Break the question into drivers that don't overlap and
   together cover the answer. Use the case-type playbook as a starting shape, then tailor
   it to this business. Each node must be answerable with data.
3. **Write hypotheses, ranked.** For the most likely branches, state a falsifiable
   hypothesis ("volume fell because dealers stopped promoting us"), the analysis that would
   prove or kill it, and the data it needs. Rank by likelihood x impact.
4. **Scan wide, then dig.** Do a quick check of every top-level branch first (the obvious
   explanation is often wrong), then go deep only where the data shows an anomaly.
5. **Update with evidence.** After each piece of evidence, mark hypotheses supported,
   killed or needs-more, and record why (fact ids, analysis ids). Kill hypotheses openly;
   don't quietly drop them.
6. **Guard against confirmation bias.** Write down competing explanations before
   researching; actively look for disconfirming data; be suspicious when the answer is
   exactly what the client already believed.
7. **Stop when** the priority hypotheses are resolved and the answer would not change with
   more data, or the budget runs out (then deliver with explicit open questions).
8. **Checkpoint.** Confirm the structure and the initial hypotheses with the client before
   investing heavily in one branch.
